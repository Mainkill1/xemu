# Circular FIFO: controlled cost and benefit

Recommendation: HOLD for the owning production draft. The circular FIFO experiment is rejected for integration: its incremental benefits are inconclusive and eight-target work is slower. This follows the previous eight-entry candidate, whose deliberate two/eight-target work measured about 25% improvement but ten targets cost 56%. The experimental implementation changes physical FIFO storage only; the current PR retains its original runtime and the useful independent correctness trace. Read production-parent results for net benefit and previous-FIFO results for the incremental effect. Do not subtract percentages across independent campaigns.

## Interpretation

The circular FIFO is rejected for integration. Its direct comparison with the previous full candidate measures +0.53% on two targets (ABBA -0.21% / BAAB +1.86%), -4.09% on eight (-4.36% / -3.99%), +2.62% on ten (+1.74% / -4.07%), and -2.00% on the noncollision control (-3.30% / +0.73%). The two-, ten-target and control order signs disagree. Every circular eight-target attempt mean is slower than every previous-FIFO mean; that is an observed regression direction, without a confidence bound. Fewer payload copies did not produce an accepted runtime gain.

The same-executable A/A is especially important: +15.94% / +7.27% / -14.57% / +3.98% in two/eight/ten/control order, despite all eight executable hashes and all six pinned input hashes matching. The first three are large apparent effects with no code change. Between-process timing variation is unclassified; Mesa correctness/measurement eligibility does not prove a stable statistical noise floor. Preserve all samples, including the fast previous-FIFO ten-target A3 = 1.061246 s. No exclusion, replacement run or subtraction from another campaign.

Compared with production parent, circular FIFO measures +33.97% / +27.48% / -33.24% / +2.08%. Both orders show fit-case gain and above-capacity loss; all four circular means beat all four parent means for two/eight targets, and all four lose for ten. This supports the synthetic victim-cache direction and its capacity cost, not the incremental ring change or retail benefit. In particular, the old -56.15% versus new -33.24% from separate parent campaigns must not be presented as a 22.91-point improvement: baselines/variation differ, and the direct FIFO ten-target comparison is inconclusive.

Owning PR #301 keeps runtime product `5679cce` and retains only the independent behavioral trace in commit `8b5ed0c`. It remains draft/HOLD: previous fit-case gains are useful, but the capacity penalty, A/A variability and missing VM/retail/cross-renderer qualification block readiness. This experiment does not justify closing the broader useful-recovery issue or performing another ring tuning pass. The next bounded work is to characterize between-process variation and search/fill cost under above-capacity misses, preserving existing safety contracts. No ring code is integrated and no merge is authorized.

## Correctness and limitations

Fresh emulator build and 15 helper cases pass locally/natively, including unchanged full-key/invalidation/alias/10,000 delayed-publication/storage-reuse checks. Experiment checks: old full implementation fails the one-payload guard (observed 8); circular implementation passes (observed 1). Independent compact-list reference covers 20,000 deterministic operations (3,256 hits, 6,746 misses, 2,848 middle promotions, 4,461 full evictions). Both faulty oldest advance and middle shift mutations are rejected. Initial trace operation/group coupling allowed a mutation to escape; original output is retained, the selector was corrected, and visited-path assertions added. A mistaken failure-log text matcher was corrected without rerunning a native measurement. Dependency/setup preflight failures and build/restoration ordering are documented in setup-notes.md.

Read-only review found no Critical/Important issue and confirmed all head positions, wraparound, logical removals, aliases and nonzero-head clears. The rejected experimental header has an unqualified padding comment, a minor documentation finding; this report qualifies that claim to the tested host. No ring code is integrated. The independent behavioral trace is retained in source commit 8b5ed0c266709736157a7341198d081111b59b3d, with 14 local/native helper checks; full-eviction one-payload guard remains specific to the archived ring experiment. A complete changed-file check confirms current draft runtime source still equals product 5679cce. Helper tests do not qualify arbitrary concurrent storage reclamation, real VM remap/second-page translation, reset/load or SMC/code-cache exhaustion. Full unit rebuild previously fails in unchanged resampler missing math declarations; full suite success is not claimed. Retail, OpenGL, broader XISO and resource checks remain required for readiness. PGR2 needs 300 seconds in a verified reached scene.
