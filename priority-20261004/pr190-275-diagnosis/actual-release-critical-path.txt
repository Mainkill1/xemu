RESULT
TCG remains almost continuously scheduled. #275 has higher cycles per control frame, with no increase in branch-miss rate or large loss of CPU availability.
Renderer work counts are nearly equal, but draw_flush host elapsed time is higher in both PR builds. This localizes a symptom, not a root cause or critical-path saving.
TCG instructions per frame differ, notably main versus #190; IPC changes cannot be assigned to code layout without matching executed work.

Every perf event reports 100% enabled/running coverage. /proc scheduler CPU time and perf task-clock differ by ~0.35s in all three runs; do not treat them as interchangeable.
Anonymous xemu threads remain unidentified in this release capture. No APU work-normalization claim is made.

Hardware measurements do not identify cache misses, cacheline bouncing, instruction-cache stalls, or helper/JIT attribution.
